# シミクレール LINEボット

ルールベースの自動応答ボットです。AI API（Claude/ChatGPT等）は使用していないため、
メッセージ量に応じた従量課金は発生しません。ランニングコストはサーバーのホスティング費用のみです。

## できること・できないこと

- FAQ（送料・発送日数・支払い方法・返品条件・使い方・定期便の有無・診察パスワード）に固定回答で即答
- 「ニキビに効きますか」等の効能質問は、個人差がある旨の定型文で自動的にかわす
- 健康被害の申告（かぶれ・赤み等）と注文トラブル（未着・破損等）には、**受付メッセージ（「担当スタッフより確認のうえ、順次ご連絡いたします」）だけを自動で返し**、内容への回答はしない
  → この2種類と、どのルールにも当たらなかったメッセージ（汎用の返信）は、
    LINE公式アカウントマネージャー（管理画面）の受信箱をスタッフが定期的に確認し、そこから直接返信してください。
    ボットが自動で医師やカウンセラーに取り次ぐことはしません（設計方針通り）。

## 必要な準備（ご自身で行ってください）

1. LINE Developersコンソールで、開設済みのLINE公式アカウントに紐づく
   「チャネルアクセストークン」と「チャネルシークレット」を発行する
   （これらは認証情報のため、私が代わりに取得・入力することはできません）
2. 上記2つを、デプロイ先の環境変数として設定する
   - `LINE_CHANNEL_ACCESS_TOKEN`
   - `LINE_CHANNEL_SECRET`
3. LINE Developersの「Messaging API設定」で、Webhook URLに
   デプロイ先のURL＋`/webhook`（例：`https://your-app.onrender.com/webhook`）を設定し、
   「Webhookの利用」をONにする
4. 応答モードを「Bot」に設定する（LINE公式アカウントマネージャーの応答設定）

## 人手を減らすための機能（2026年11月追加）

| 機能 | 内容 | 必要な設定 |
|---|---|---|
| 注文トラブルの受付文 | 注文番号・お名前・内容（破損・誤配送は写真）を最初にもらう | なし |
| 営業時間外の案内 | スタッフ対応に回る返信に、時間外なら「翌営業日以降のご連絡」の一文を添える（平日10:00〜19:00、土日祝・12/29〜1/3は休業） | なし |
| 健康被害の通知 | 健康被害の連絡が来たら、スタッフのLINEグループへすぐ通知（本文は載せない） | `STAFF_NOTIFY_TO` |
| リッチメニュー | トーク画面下の6つのボタン。押すと決まった返信が返る | LINE公式アカウントマネージャーで作成 |
| 配送状況の自動確認 | 注文番号＋注文時のメールアドレス（または電話番号）が送られたら、Shopifyで調べて返す | `SHOPIFY_SHOP` ほか |

### 健康被害の通知の設定

1. LINE公式アカウントマネージャーの「設定」→「アカウント設定」で「グループ・複数人トークへの参加を許可する」をオンにする
2. スタッフのLINEグループにこの公式アカウントを招待する。ボットがグループIDを返信する
3. Renderの環境変数 `STAFF_NOTIFY_TO` にそのID（`C`から始まる）を設定する（複数ならカンマ区切り）
4. 通知はLINEのプッシュメッセージで送るため、公式アカウントの月間メッセージ数に含まれる
5. ボットはグループ内の会話には返信しない（お客様との1対1のトークだけに返信する）

### リッチメニューの設定

LINE公式アカウントマネージャーの「リッチメニュー」→「作成」で、テンプレート「大」の6分割（上段A・B・C、下段D・E・F）を選び、
画像に `richmenu/themes/stone-<テーマ>.jpg` のどれか1枚（2500×1686）をアップロードする。Aだけアクションを「リンク」、ほかは「テキスト」にして、次の内容を**一字一句そのまま**入れる。

| 位置 | 画像の表示 | アクション | 設定する内容 |
|---|---|---|---|
| A | 商品を見る | リンク | https://simiclair.myshopify.com |
| B | 送料・お支払い | テキスト | 送料・お支払いについて |
| C | 返品・交換 | テキスト | 返品・交換について |
| D | 専売品の購入方法 | テキスト | 専売品の購入方法 |
| E | ご注文状況の確認 | テキスト | ご注文状況の確認 |
| F | その他のお問い合わせ | テキスト | その他のお問い合わせ |

文言は `index.js` の `MENU_REPLIES` と一致している必要がある。画像を作り直すときは `richmenu/richmenu.html` を編集して書き出す。

`richmenu/themes/stone-<テーマ>.jpg`（2026年11月作成、各1MB未満）は、当院のメニュー画像を元に LANE RESERVE の8つのカラーテーマ
（default 華やか／blush ピンクベージュ／calm 爽やか／seiji 青白磁とリネン／hakuji ホワイト／solemn 厳か／luxe ゴールド／natural シェル）で色を変えたもの。
シェルは白蝶貝の真珠層、ゴールドはサテン（どちらも LANE RESERVE の背景テクスチャを石ごとに向きを変えて重ねたもの）、
ホワイトと爽やかは縁が光る陶器の強いつや、青白磁とリネンは強弱がばらつく自然な石のざらつき、華やかと厳かはプラチナのきらめきのアベンチュリン
（どちらもロイヤルオーク・フロステッドのような、ごく細かく密な霜のきらめき）。
8枚ともボタンの並びは上の表と同じ。`richmenu/richmenu.png` は最初の仮の画像で、ボタンの並びが古い（送料・お届け／お支払い方法が別々）。
以前の並びの文言（送料・お届けについて／お支払い方法について）にもボットは今も答える。

### 配送状況の自動確認の設定（Shopify）

1. Shopifyの Dev Dashboard（dev.shopify.com）でアプリを作り、アクセス権に `read_orders` を選ぶ
   （60日より前の注文も調べる場合は `read_all_orders` も必要）
2. 注文のメールアドレス・電話番号を照合に使うため、アプリの設定で保護された顧客データ（メールアドレス・電話番号）へのアクセスを申請する
3. アプリをストア（`ehhk60-bq.myshopify.com`）にインストールする（アプリとストアが同じ組織にあること）
4. Renderの環境変数に次を設定する（クライアントシークレットは秘密情報。チャットやGitHubには載せない）
   - `SHOPIFY_SHOP`：`ehhk60-bq`
   - `SHOPIFY_CLIENT_ID`：アプリのクライアントID
   - `SHOPIFY_CLIENT_SECRET`：アプリのクライアントシークレット
   - `SHOPIFY_API_VERSION`：省略可（既定は `2026-10`）
5. 3つがそろうまでこの機能は動かず、案内文にも出ない

安全のための決まり：
- 注文番号に加え、注文時のメールアドレスか電話番号が一致したときだけ答える。見つからない場合と一致しない場合は同じ返信にする
- 返すのは支払い・発送の状況と追跡番号のみ（住所・氏名・商品などは返さない）
- 同じ人からの確認は10分に5回まで。メールアドレス・電話番号はログに残さない
- 健康被害の言葉を含むメッセージは、注文確認より健康被害の扱いを優先する
- 「#1001」だけが届いたら連絡先をお願いし、注文番号を15分だけ覚える（同じ人が続けてメールアドレスか電話番号だけを送れば調べる）。
  連絡先だけが届いたら注文番号をお願いする。覚えるのは注文番号だけで、サーバーの再起動で消える
- 全角・半角、「〜です」などの語尾、「注文番号：」「No.」「1001番」、電話番号の「ー」や空白、番号とメールアドレスの続け書きに対応。
  金額などを注文番号と取り違えないよう、連絡先がないときは「#」「注文」「番号」などが付いた番号か数字だけのメッセージに限る
- 追跡番号は、Shopifyで発送済みにするときに入力した配送会社・追跡番号・追跡URLをそのまま返す（未入力なら発送完了メールの確認をお願いする）
- 配送会社名は「Yamato (JA)」などでも「ヤマト運輸／佐川急便／日本郵便」と日本語で表示する。追跡URLが入っていないときは、
  ヤマト・佐川・日本郵便なら追跡番号から各社の追跡ページのURLを組み立てて付ける（それ以外の会社はURLなし）

## LINEの「Webhookの再送」への備え

LINE Developers の「Webhookの再送」をオンにすると、ボットが一時的に受け取れなかったイベントをLINEが送り直す。
そのとき同じイベントが2回届いたり、届く順番が入れ替わったりすることがあるため、次のようにしている。

- 同じイベントID（webhookEventId）は1時間覚えておき、2回目は無視する（返信・スタッフ通知・確認回数が重ならない）
- 「#1001」→連絡先の2回に分けた確認は、お客様が送った時刻（timestamp）で比べ、連絡先が注文番号より後に送られたときだけ組み合わせる

## スリープ対策（Renderの無料プラン）

Renderの無料プランは、15分間アクセスがないと止まり、次のメッセージで起きるまで最大1分ほどかかる（その間は既読も返信も遅れる）。
外部の監視サービス（UptimeRobot など）から `https://simiclair-line-bot.onrender.com/health` に10分以内の間隔でアクセスさせて、止まらないようにしている。
`/health` は「ok」を返すだけで、LINEの処理は通らない。

- 無料プランは月750時間まで。このサービス1つを止めずに動かすと1か月で約744時間なので、Renderにほかの無料サービスを置くと枠を超えて月末まで止まるおそれがある
- 確実にするなら、Renderの有料インスタンスに切り替える（スリープしなくなり、監視サービスは不要になる）

## 回答内容のカスタマイズ

返品は不良品・誤配送のみ到着後7日以内）は、2026年11月時点のShopifyの設定・ポリシーに合わせています。
ストアの設定を変えたら、ここも必ず直してください。

## 精度の目安と限界（2026年11月10日の試験）

- 精度は「修正に使っていない新しい質問」で測る。チューニング済みの `cases.json` の100%は実力ではない
- 11月10日：新しい質問42問（`test/holdout-2026-11-10.json`）で、改善前81% → 改善後83%（35/42）
  - 外れ7件のうち5件は汎用の返信（スタッフ対応）に回ったもの。誤った事実（送料・支払い方法など）を返したものは0件
  - 1件だけ関係のない定型文を返した（「明日までに欲しいのですが間に合いますか」に効能の定型文）→ その後修正済み
  - 外れた例は `cases.json` に追加して修正済み。このため、このセットはもう「新しい質問」としては使えない。次回は別の新しい質問を作って測る
- 解消済みの誤検知：「ポイントカード」→支払い回答、「痛快」→健康被害扱い、「変更点」→注文トラブル扱い（`index.js` の `NEUTRAL_WORDS`）
- キーワード一致のため、言い回しが想定外だと汎用の返信になる。汎用の返信の受信箱確認は必須
- 誤検知・取りこぼしを見つけたら `test/cases.json` に追加してからキーワードを直す

## さらに精度を上げたい場合（案）：AIに「分類だけ」させる

AIに自由に回答させるのではなく、「この質問は送料・支払い・健康被害…のどれか」だけをAI（Claude API）に判定させ、
返信は今と同じ固定文から選ぶ方式。誤った情報や効能の断言をAIが書く余地はない。

- 費用の目安：最も安い Claude Haiku 5.5（入力100万トークンあたり0.10ドル、出力0.50ドル）で、1通あたり約0.0001ドル。
  月1,000通でも約15円程度
- 安全策：健康被害の言葉（かぶれ・赤み等）はAIより先にキーワードで判定して必ずスタッフ対応に回す。
  AIの応答が遅い・失敗した・自信がない場合は汎用の返信（スタッフ対応）に回す
- 必要なもの：AnthropicのAPIキー（サーバーの環境変数に設定。チャットには貼らない）
- 導入前に、今と同じ方法（新しい質問セット）で精度を比べてから判断する
